# Psych Ward OS — команды шелла

Полный справочник всех команд, доступных в интерактивном шелле (`sandbox[N] /путь>`). Общий обзор проекта — в [README.md](../README.md), подробности по фазам разработки — в [ROADMAP.md](ROADMAP.md).

Условные обозначения: `<...>` — обязательный аргумент, `[...]` — необязательный, `|` — варианты на выбор.

## Встроенные команды шелла (`shell.cpp`)

| Команда | Флаги/аргументы | Краткое описание |
|---|---|---|
| `help` | — | список всех доступных команд (одной строкой) |
| `time` | — | текущее время, мс с эпохи |
| `uptime` | — | время работы системы с загрузки |
| `date` | — | локальные дата и время |
| `temp` | — | температура CPU (датчик AVS) |
| `mboxprobe` | — | диагностика: жив ли VideoCore mailbox |
| `cpufreq` | `[set min\|max]` | без аргумента — текущая/мин/макс частота ARM; с `set` — принудительно переключить (DVFS) |
| `peripherals` | — | состояние энергодоменов VideoCore (HDMI/камера/видео/3D — включены/выключены) |
| `sleep` | `[мс]` | пауза (по умолчанию 3000 мс) |
| `ping` | `[-W] <хост\|IP> [count]` | ICMP ping; `-W` — через Wi-Fi вместо Ethernet (GENET) по умолчанию |
| `send` | `[-W] <текст>` | отправить UDP-датаграмму на `10.0.2.2:8080` |
| `sendto` | `[-W] <IP> <порт> <текст>` | отправить UDP-датаграмму на произвольный адрес |
| `netstat` | — | статус обоих сетевых интерфейсов (Ethernet + Wi-Fi) |
| `recv` | `[-W]` | получить накопившиеся входящие UDP-данные |
| `ntp` | `[status]` | синхронизация времени по SNTP; `status` — офсет и время последней/следующей ресинхронизации |
| `wifiprobe` | — | низкоуровневая диагностика SDIO/прошивки Wi-Fi-модуля |
| `wifi start` | `[-l]` | запустить `wifi_driver` (SDIO/firmware bring-up в фоне); `-l` — дождаться и напечатать итоговый статус |
| `wifi stop` | `[-l]` | остановить `wifi_driver` |
| `wifi restart` | `[-l]` | перезапустить `wifi_driver` |
| `wifi scan` | `[-l] [-t сек] [-f 2\|5]` | сканирование сетей; `-t` — таймаут (по умолч. 30с), `-f` — только диапазон 2.4/5 ГГц (по умолч. оба) |
| `wifi connect` | `<ssid> [пароль] [-l] [&&save]` | подключиться к сети; без пароля — берётся из сохранённых известных сетей; `&&save` — запомнить пароль |
| `wifi clean` | `[all] [-l]` | забыть пароль текущей сети либо все сохранённые (`all`) |
| `wifi status` | — | подробный статус Wi-Fi (SDIO/прошивка/линк/SSID/MAC) |
| `pwd` | — | текущий рабочий каталог |
| `history` | — | история введённых команд |
| `cd` | `[путь]` | сменить каталог (без аргумента — в `/`) |
| `exec` | `<файл> [аргументы] [&]` | запустить ELF-файл; `&` — в фоне, без ожидания завершения |
| `shm` | `<id> <read\|write> [текст]` | прочитать/записать отладочную страницу SHM по номеру |
| `recover` | `<имя_процесса>` | принудительный watchdog-респавн (kill + полное пересоздание) процесса по имени |
| `driver` | `<имя> <stop\|start\|restart>` | лёгкий сигнал драйверу без убийства процесса: `stop`/`start` — остановить/возобновить обработку команд, `restart` — повторная инициализация железа на том же PID (поддерживается для `blk_driver`/`net_driver`/`usb_driver`/`wifi_driver`; `uart_driver`/`timer_driver` — только `stop`/`start`, `restart` не поддержан) |
| `pid` | — | PID текущего процесса шелла |
| `echo` | `<текст> [> файл]` | вывести текст; с `>` — записать (перезаписать) в файл |
| `exit` | — | завершить сессию шелла |
| `crash_shell` | — | тестовый краш самого шелла (разыменование null) — для отладки |
| `crash_disk` | — | тестовый краш `blk_driver` — для отладки |
| `./файл` | — | запустить ELF из текущего каталога (то же, что `exec`, короткий синтаксис) |
| <code>команда &#124; grep &lt;шаблон&gt;</code> | — | конвейер: вывод команды слева фильтруется по подстроке справа (`grep` — единственная поддержанная правая часть) |

## Внешние утилиты `/sbin` (отдельные `.elf`, `shell.cpp` передаёт им управление напрямую)

| Команда | Флаги/аргументы | Краткое описание |
|---|---|---|
| `ls` | `[путь]` | список файлов каталога (без аргумента — текущий) |
| `cat` | `<файл>` | вывести содержимое файла |
| `touch` | `<файл...>` | создать файл(ы) (можно несколько за раз) |
| `rm` | `<файл...>` | удалить файл(ы) (можно несколько за раз) |
| `mv` | `<старое_имя> <новое_имя>` | переименовать/переместить файл |
| `mkdir` | `<каталог...>` | создать каталог(и) (можно несколько за раз) |
| `ps` | — | список процессов (PID/статус/имя) |
| `kill` | `<pid>` | завершить процесс по PID |
| `taskset` | `<pid> <ядро 0-3>` | привязать процесс к конкретному ядру |
| `top` | `[-l]` | нагрузка по ядрам; `-l` — подробная построчная таблица по процессам |
| `balance` | — | принудительно запустить один проход балансировщика нагрузки по ядрам |
| `usb` | — | информация о первом найденном USB-устройстве |
| `df` | `[-h]` | занятое/свободное место (SD-карта + все смонтированные USB-тома); `-h` — в человекочитаемых единицах (K/M/G/T) |
| `free` | — | использование RAM (Total/Used/Free) |

## Тестовые хуки `/sbin` (`PSYCH_TEST_TOOLS` в CMakeLists.txt, каждый — постоянный регрессионный тест под конкретный пункт issuse.txt)

| Команда | Флаги/аргументы | Краткое описание |
|---|---|---|
| `holdshm` | `[секунды]` | держит выданный SHM и ничего не делает N секунд (по умолч. 20) — окно для ручного `kill <pid>` живого процесса |
| `proxytest` | — | бьёт по SYS_PROXY_WRITE_FILE/SYS_PROXY_READ_FILE с заведомо неверной длиной данных (issuse.txt №4/№66) |
| `recovertest` | `<имя_процесса>` | сырой SYS_RECOVER от лица вызывающего процесса — проверка admin-check (issuse.txt №3); чтобы получить untrusted-вызов (`is_driver=254`), запускать БЕЗ буквального префикса `/sbin/` в команде (например `cd /sbin`, затем `exec recovertest.elf <имя>`) |

---

Список команд в `help` внутри шелла на момент написания устарел (не включает `top`/`taskset`/`balance`/`usb`/`df`/`free`/`recover`/`driver`) — этот файл актуальнее.

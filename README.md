# 🧠 Psych Ward OS: True Microkernel Edition

**Psych Ward OS** — это экспериментальная операционная система на базе микроядра **seL4**, реализующая принцип наименьших привилегий и полную изоляцию компонентов. В отличие от монолитных систем, здесь даже драйверы устройств и системные службы вынесены в пространство пользователя (User-space)[cite: 1].

## 🏗 Архитектура: Модульная Изоляция

Проект перешел от монолитного приложения к модульной структуре. Теперь пользовательское окружение разделено на три независимых бинарника, каждый из которых работает в собственной песочнице[cite: 1]:

1.  **UART Driver (`uart_driver.cpp`):** Изолированный сервер терминала. Владеет физическим фреймом ввода-вывода и обрабатывает прерывания клавиатуры[cite: 1].
2.  **Timer Driver (`timer_driver.cpp`):** Служба системного времени. Управляет RTC и предоставляет сервис засыпания через IPC[cite: 1].
3.  **Shell (`shell.cpp`):** Пользовательская оболочка, обеспечивающая интерфейс управления и порождение новых процессов[cite: 1].

**Rootserver (The Doctor)** в `main.cpp` выполняет роль верховного судьи: управляет адресными пространствами, раздает права (Capabilities) и координирует системные вызовы[cite: 1].

## 🚀 Ключевые возможности

*   **User-Space Driver Isolation:** Драйверы работают как обычные процессы. Ошибки в коде драйвера не приводят к панике ядра[cite: 1].
*   **Process Lifecycle (POSIX-like):** Реализованы системные вызовы `SYS_EXEC` (запуск ELF), `SYS_WAIT` (ожидание завершения) и `SYS_EXIT` (самозавершение)[cite: 1].
*   **Demand Paging:** Динамический аллокатор страниц выделяет память на лету при возникновении Page Fault[cite: 1].
*   **Zero-Copy Shared Memory:** Использование разделяемой страницы для передачи данных VFS и списка процессов между ядром и оболочкой[cite: 1].

## 🐜 Post-Mortem: Анатомия "Матрешки" (The Exit Hang & IPC Blackhole)

В процессе реализации многозадачности (запуск дочерней оболочки из родительской) мы столкнулись с каскадным сбоем, который приводил к "тихому" зависанию всей системы. Вот разбор трех всадников микроядерного апокалипсиса, с которыми мы успешно справились:

### 1. The Timer Trap (Битовое пересечение бейджей)
*   **Симптом:** Любая команда в оболочке приводила к бесконечному зависанию `seL4_Call`.
*   **Причина:** Rootserver проверял аппаратные прерывания по битовой маске (`sender_badge & TIMER_IRQ_BADGE`, где маска таймера = 2). Так как `shell` получил PID 3 (в двоичной системе `0011`), логическая операция `3 & 2` давала `ИСТИНУ`. Rootserver принимал системный вызов оболочки за "тик" таймера, молча глушил его и уходил на следующий круг цикла.
*   **Решение:** Полная очистка Rootserver'а от обработки прерываний. Теперь прерываниями занимаются исключительно изолированные User-space драйверы.

### 2. The Faceless Process (Потерянный сигнал пробуждения)
*   **Симптом:** При убийстве дочернего процесса (`kill 4`), он корректно завершался, но родитель (PID 3) навсегда оставался спать.
*   **Причина:** Оболочке передавалась немаркированная (unbadged) капа корневого эндпоинта. При вызове `SYS_WAIT` ядро видело отправителя с `badge = 0` и сохраняло сигнал пробуждения (Reply Cap) в "нулевой" процесс. При смерти ребенка цикл поиска спящих родителей начинался с индекса `1`, пропуская "нулевой" слот.
*   **Решение:** Строгая передача именной капы `badged_ep` в `ipc_buffer->userData` при порождении любого процесса. Теперь каждый процесс имеет свой уникальный "паспорт" (PID) на уровне аппаратных механизмов seL4.

### 3. The Zombie Array (Мусор в памяти)
*   **Симптом:** Вызов `ps` приводил к падению Rootserver'а с Page Fault.
*   **Причина:** Глобальный массив структур `pcbs[256]` не очищался при старте системы. Ядро пыталось читать имена процессов-призраков по случайным адресам из мусорной памяти QEMU.
*   **Решение:** Принудительная инициализация памяти `memset(pcbs, 0, sizeof(pcbs))` на этапе загрузки (Bootstrapping).

## 💻 Сборка и запуск

### Зависимости:
*   `arm-none-eabi` или `aarch64-linux-gnu` toolchain
*   `QEMU` (для эмуляции virt/cortex-a53)
*   `Ninja` и `CMake`

### Компиляция:
```bash
mkdir build && cd build
../init-build.sh -DPLATFORM=qemu-arm-virt -DAARCH64=1
ninja
```

### Запуск в QEMU:
```bash
qemu-system-aarch64 \
    -machine virt,virtualization=on \
    -cpu cortex-a53 \
    -nographic \
    -serial mon:stdio \
    -m size=1024M \
    -kernel images/sel4test-driver-image-arm-qemu-arm-virt
```

### Пуш в GitHub:
```bash
git add .
git commit -a -m "."
git push origin main

```

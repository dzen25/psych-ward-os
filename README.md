# 🧠 Psych Ward OS — Порт на Raspberry Pi 4

**Psych Ward OS** — экспериментальная ОС на базе микроядра **seL4** (принцип наименьших привилегий, полная изоляция компонентов, самовосстановление). Ветка `main` — стабильная версия для **QEMU** (`qemu-arm-virt`), разработка там завершена.

**Эта ветка (`RPi4`)** — активный порт на реальное железо: **Raspberry Pi 4 B (BCM2711, Cortex-A72, AArch64)**. Всё содержимое этого README относится только к порту; архитектура ядра ОС, команды shell и инструкции по сборке под QEMU описаны в README ветки `main`.

---

## Почему RPi4

seL4 официально поддерживает Raspberry Pi 4 (`-DPLATFORM=rpi4`, unverified, maintained by seL4 Foundation). Это резко снижает риск порта по сравнению со старой идеей таргета MT6260CA/ARMv5, который seL4 вообще не поддерживает.

---

## Что нужно портировать

На QEMU (`qemu-arm-virt`) диск, сеть и время эмулируются через virtio и PL031 — ничего из этого физически не существует на реальной плате. Ниже — по каким подсистемам нужны настоящие драйверы.

**Обязательно для базового порта** (без этого `psych-ward-os` не заработает на железе — см. Фазу 3 в [ROADMAP.md](ROADMAP.md)):

- [ ] **Диск:** `virtio-blk` → EMMC2/SD-контроллер BCM2711 (свой драйвер, FAT32-логика поверх переиспользуется как есть)
- [ ] **Сеть:** `virtio-net` → genet, Ethernet MAC BCM2711 (свой драйвер, ARP/UDP/NTP/DNS-логика поверх переиспользуется как есть)
- [ ] **RTC/время:** PL031 (battery-backed RTC) физически отсутствует на плате → ARM generic timer (`CNTPCT_EL0`) для аптайма + уже готовый NTP-клиент как источник wall-clock
- [ ] **UART/GIC:** PL011/GICv2 на плате те же самые, что и на QEMU — низкий риск, нужны только другие адреса в `platform.h`

**Не задействовано в текущей архитектуре Psych Ward OS** (headless-система, единственный интерфейс — serial UART), но каталогизируем на будущее, чтобы не забыть при расширении функционала:

- [ ] USB (host-контроллер — понадобится, например, для клавиатуры или внешних накопителей помимо SD)
- [ ] Wi-Fi / Bluetooth (BCM43455, отдельный SDIO-стек — сильно отличается от genet)
- [ ] GPIO (общее управление пинами, если появится периферия помимо UART/сети/диска)
- [ ] HDMI (видеовывод — сейчас не нужен, вся ОС работает через serial)
- [ ] Аудио (PWM/I2S audio out — не используется)
- [ ] PCIe (внешняя шина RPi4 — потенциально для будущих ускорителей/сетевых карт)

Подробный пошаговый чек-лист по каждому пункту — в [ROADMAP.md](ROADMAP.md).

<details>
<summary><b>📂 Структура порта: где что лежит и зачем (клик, чтобы развернуть)</b></summary>

В репозитории две отдельные папки с файлами цепочки загрузки — не перепутать:

- **`load_chain_test/`** — файлы для Фазы 1 (проверка связи/тулчейна): чистый `sel4test` hello-world образ (`sel4test-driver-image-arm-bcm2711`). Смысл в том, чтобы протестировать цепочку загрузки (GPU firmware → U-Boot → seL4) полностью изолированно от кода `psych-ward-os`. Этот образ поддерживается и разрабатывается seL4 Foundation — если он не грузится, проблема гарантированно в тулчейне, SD-карте или проводах, а не в собственном коде проекта. Только после того как этот образ подтверждённо загружается на живом железе, есть смысл переходить к порту самого `psych-ward-os` (Фаза 3).
- **`load_chain/`** — файлы для полноценной загрузки уже готового образа `psych-ward-os` (Фаза 3 и далее). Цепочка та же самая (`start4.elf`, `fixup4.dat`, `bcm2711-rpi-4-b.dtb`, `config.txt`, `u-boot.bin`) — эти файлы не зависят от того, какая ОС грузится, поэтому переиспользуются один в один. Меняется только последний файл — вместо тестового `sel4test` образа туда кладётся итоговый собранный `psych-ward-os`. На момент написания в папке ещё нет финального образа — появится после успешного прохождения Фазы 3.

На хост-машине (вне репозитория) заведена рабочая папка `RPi4_SeL4/` с исходниками: `load_chain/` (сырые файлы до копирования в репозиторий), `u-boot/` (клон и сборка U-Boot), `sel4-rpi4-hello/` (отдельное дерево sel4test для проверки hello-world, **не** `psych-ward-os`). Она держится вне git осознанно: это склонированные сторонние деревья (исходники U-Boot, весь `sel4test-manifest` через `repo`) — десятки-сотни МБ временных/сборочных файлов, в репозиторий должны попадать только конечные артефакты (уже собранные бинарники), а не сырые чужие исходники.

</details>

<details>
<summary><b>⚙️ Зависимости хоста (клик, чтобы развернуть)</b></summary>

В дополнение к пакетам из ветки `main` (тулчейн `aarch64-linux-gnu`, `cmake`, `ninja`, `python3-venv`) для работы над портом нужны:

```bash
sudo apt install -y device-tree-compiler u-boot-tools minicom
```

- `device-tree-compiler` — `dtc`, декомпиляция `.dtb` → `.dts` (Фаза 2).
- `u-boot-tools` — `mkimage`, сборка `boot.scr` (Фаза 1.6).
- `minicom` (или `screen`/`picocom`) — serial-консоль к плате через USB-UART переходник.

Репозиторий `repo` (Google) нужен отдельно для сборки чистого sel4test hello-world (см. Фазу 1.3):

```bash
mkdir -p ~/.bin && curl https://storage.googleapis.com/git-repo-downloads/repo > ~/.bin/repo
chmod a+x ~/.bin/repo
export PATH=~/.bin:$PATH
```

Дерево `sel4-rpi4-hello` (Фаза 1.3) собирается тем же способом, что и `psych-ward-os` на `main` — нужно то же самое изолированное виртуальное окружение Python и те же зависимости из `requirements.txt`:

```bash
python3 -m venv ~/sel4-vibe
source ~/sel4-vibe/bin/activate
pip install -r requirements.txt
```

(если venv `~/sel4-vibe` уже создан для сборки под QEMU на `main` — просто активировать его заново, пересоздавать не нужно)

</details>

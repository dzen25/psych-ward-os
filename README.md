# 🧠 Psych Ward OS — Порт на Raspberry Pi 4

**Psych Ward OS** — экспериментальная ОС на базе микроядра **seL4** (принцип наименьших привилегий, полная изоляция компонентов, самовосстановление). Ветка `main` — стабильная версия для **QEMU** (`qemu-arm-virt`), разработка там завершена.

**Эта ветка (`RPi4`)** — активный порт на реальное железо: **Raspberry Pi 4 B (BCM2711, Cortex-A72, AArch64)**. Всё содержимое этого README относится только к порту; архитектура ядра ОС, команды shell и инструкции по сборке под QEMU описаны в README ветки `main`.

## Почему RPi4

seL4 официально поддерживает Raspberry Pi 4 (`-DPLATFORM=rpi4`, unverified, maintained by seL4 Foundation). Это резко снижает риск порта по сравнению со старой идеей таргета MT6260CA/ARMv5, который seL4 вообще не поддерживает.

<details>
<summary><b>📂 Структура порта: где что лежит и зачем (клик, чтобы развернуть)</b></summary>

В репозитории две отдельные папки с файлами цепочки загрузки — не перепутать:

- **`load_chain_test/`** — файлы для Фазы 1 (проверка связи/тулчейна): чистый `sel4test` hello-world образ (`sel4test-driver-image-arm-bcm2711`). Смысл в том, чтобы протестировать цепочку загрузки (GPU firmware → U-Boot → seL4) полностью изолированно от кода `psych-ward-os`. Этот образ поддерживается и разрабатывается seL4 Foundation — если он не грузится, проблема гарантированно в тулчейне, SD-карте или проводах, а не в собственном коде проекта. Только после того как этот образ подтверждённо загружается на живом железе, есть смысл переходить к порту самого `psych-ward-os` (Фаза 3). Полный, самодостаточный цикл (свой U-Boot, без Фазы 13/подписи) — **[load_chain_test/INSTRUCTIONS.md](load_chain_test/INSTRUCTIONS.md)**.
- **`load_chain/`** — файлы для полноценной загрузки уже готового образа `psych-ward-os` (Фаза 3 и далее). `start4.elf`/`fixup4.dat`/`bcm2711-rpi-4-b.dtb`/`config.txt` не зависят от ОС и переиспользуются с `load_chain_test/` один в один — но `u-boot.bin` **НЕТ**: с Фазы 13 у него другая сборка (проверка подписи, зашитая boot-команда), и `boot.scr` тут больше не используется (заменён подписанным `boot.itb`). См. **[INSTRUCTIONS.md](INSTRUCTIONS.md)**.

На хост-машине (вне репозитория) заведена рабочая папка `RPi4_SeL4/` с исходниками: `load_chain/` (сырые файлы до копирования в репозиторий), `u-boot/` (клон и сборка U-Boot), `sel4-rpi4-hello/` (отдельное дерево sel4test для проверки hello-world, **не** `psych-ward-os`). Она держится вне git осознанно: это склонированные сторонние деревья (исходники U-Boot, весь `sel4test-manifest` через `repo`) — десятки-сотни МБ временных/сборочных файлов, в репозиторий должны попадать только конечные артефакты (уже собранные бинарники), а не сырые чужие исходники.

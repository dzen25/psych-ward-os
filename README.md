# 🧠 Psych Ward OS — Порт на Raspberry Pi 4

**Psych Ward OS** — экспериментальная ОС на базе микроядра **seL4** (принцип наименьших привилегий, полная изоляция компонентов, самовосстановление). Ветка `main` — стабильная версия для **QEMU** (`qemu-arm-virt`), разработка там завершена.

**Эта ветка (`RPi4`)** — активный порт на реальное железо: **Raspberry Pi 4 B (BCM2711, Cortex-A72, AArch64)**. Всё содержимое этого README относится только к порту; архитектура ядра ОС, команды shell и инструкции по сборке под QEMU описаны в README ветки `main`.

---

## Почему RPi4

seL4 официально поддерживает Raspberry Pi 4 (`-DPLATFORM=rpi4`, unverified, maintained by seL4 Foundation). Это резко снижает риск порта по сравнению со старой идеей таргета MT6260CA/ARMv5, который seL4 вообще не поддерживает.

---

## Что нужно портировать

На QEMU (`qemu-arm-virt`) диск, сеть и время эмулируются через virtio и PL031 — ничего из этого физически не существует на реальной плате. Портирование всего железа, необходимого для полноценной сетевой headless-системы, **завершено** и подтверждено на живом железе (Фазы 3–4 в [ROADMAP.md](ROADMAP.md)):

- [x] **Диск:** `virtio-blk` → EMMC2/SD-контроллер BCM2711 (свой драйвер, FAT32-логика поверх переиспользуется как есть)
- [x] **Сеть (Ethernet):** `virtio-net` → genet, Ethernet MAC BCM2711 (свой драйвер + DHCP/ARP-клиент поверх; ARP/UDP/NTP/DNS-логика переиспользуется как есть)
- [x] **RTC/время:** PL031 (battery-backed RTC) физически отсутствует на плате → ARM generic timer (`CNTVCT_EL0`, не `CNTPCT_EL0` — см. ROADMAP 3.1) для аптайма + NTP-клиент как источник wall-clock
- [x] **UART/GIC:** PL011/GICv2 на плате те же самые, что и на QEMU — только другие адреса в `platform.h`, подробнее про отладку в папке `uart-wifi_JTAG`, интерфейс — serial UART

Портирование железа на этом закончено — дальше работа не над новым железом, а над надстройками поверх уже работающих систем.

Дальше в работе (Фаза 4 в ROADMAP.md):
- [x] **Wi-Fi:** BCM43455 (отдельный SDIO-стек, сильно отличается от genet) — bring-up, подключение к точке доступа (SSID/WPA2-PSK) и полная интеграция в общий сетевой стек: DHCP/ARP/ping/DNS/NTP работают через Wi-Fi так же, как через Ethernet, включая полноценный dual-stack (оба интерфейса одновременно, каждый со своим IP)

Дальше в работе (Фаза 5 в ROADMAP.md):
- [x] **Безопасность:** SHM-доступ по ролевой таблице capability (least-privilege) — `exec`-процессы получают ноль страниц (VFS-доступ через узкий root-прокси), права там, где возможно, сокращены до read-only, Wi-Fi-пароль обнуляется сразу после использования, низкочастотные мейлбоксы (ping) переведены на настоящий IPC

Дальше в работе (Фаза 6 в ROADMAP.md):
- [x] **Многоядерность (SMP):** все 4 ARM-ядра платы загружаются (spin-table), `wifi_driver` перенесён на второе ядро; общий доступ к VFS-прокси SHM (shell/net_driver/wifi_driver) переведён с non-atomic спинлоков на мьютекс поверх seL4-нотификации — hardware-atomic на этой (Device-)памяти небезопасен

Дальше в работе (Фаза 7 в ROADMAP.md):
- [ ] **DVFS/cpufreq:** снижение частоты/напряжения ARM-ядер в простое — сейчас на паузе (VideoCore mailbox не отвечает на этой связке загрузчика/прошивки, см. подробности в ROADMAP)

Дальше в работе (Фаза 8 в ROADMAP.md):
**Не задействовано в текущей архитектуре** (headless-система):

- [ ] USB (host-контроллер — понадобится, например, для клавиатуры или внешних накопителей помимо SD)
- [ ] GPIO (общее управление пинами, если появится периферия помимо UART/сети/диска)
- [ ] HDMI (видеовывод — сейчас не нужен, вся ОС работает через serial)
- [ ] Аудио (PWM/I2S audio out — не используется)
- [ ] PCIe (внешняя шина RPi4 — потенциально для будущих ускорителей/сетевых карт)

Подробности по каждому пункту — в [ROADMAP.md](ROADMAP.md).

<details>
<summary><b>📂 Структура порта: где что лежит и зачем (клик, чтобы развернуть)</b></summary>

В репозитории две отдельные папки с файлами цепочки загрузки — не перепутать:

- **`load_chain_test/`** — файлы для Фазы 1 (проверка связи/тулчейна): чистый `sel4test` hello-world образ (`sel4test-driver-image-arm-bcm2711`). Смысл в том, чтобы протестировать цепочку загрузки (GPU firmware → U-Boot → seL4) полностью изолированно от кода `psych-ward-os`. Этот образ поддерживается и разрабатывается seL4 Foundation — если он не грузится, проблема гарантированно в тулчейне, SD-карте или проводах, а не в собственном коде проекта. Только после того как этот образ подтверждённо загружается на живом железе, есть смысл переходить к порту самого `psych-ward-os` (Фаза 3).
- **`load_chain/`** — файлы для полноценной загрузки уже готового образа `psych-ward-os` (Фаза 3 и далее). Цепочка та же самая (`start4.elf`, `fixup4.dat`, `bcm2711-rpi-4-b.dtb`, `config.txt`, `u-boot.bin`, `boot.scr`) — эти файлы не зависят от того, какая ОС грузится, поэтому переиспользуются один в один. Меняется только последний файл — вместо тестового `sel4test` образа туда кладётся итоговый собранный `psych-ward-os`. Начиная с Фазы 3 в папке лежит актуальный собранный образ — обновляется при каждой пересборке. С Фазы 4 (Wi-Fi) в папке появились два новых подкаталога:
  - **`overlays/`** — device-tree оверлей `disable-bt.dtbo`: у BCM43455 общий SDIO/UART на Wi-Fi и Bluetooth, а драйвера Bluetooth в проекте нет.
  - **`wifi/`** — прошивка/NVRAM/CLM-блоб чипа (`wifi_fw.bin`, `wifi_nvram.txt`, `wifi_clm.bin`) — обычные файлы на FAT32-разделе SD-карты (не часть seL4-образа), `wifi_driver.cpp` читает их через `blk_driver` во время `wifi start`.

На хост-машине (вне репозитория) заведена рабочая папка `RPi4_SeL4/` с исходниками: `load_chain/` (сырые файлы до копирования в репозиторий), `u-boot/` (клон и сборка U-Boot), `sel4-rpi4-hello/` (отдельное дерево sel4test для проверки hello-world, **не** `psych-ward-os`). Она держится вне git осознанно: это склонированные сторонние деревья (исходники U-Boot, весь `sel4test-manifest` через `repo`) — десятки-сотни МБ временных/сборочных файлов, в репозиторий должны попадать только конечные артефакты (уже собранные бинарники), а не сырые чужие исходники.

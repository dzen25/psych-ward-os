## 📤 Работа с Git и публикация на GitHub

Здесь собрано всё необходимое для старта работы с кодом ОС. Если вы только что установили Git на свежую систему, начните с первого шага. Если Git уже настроен — переходите ко второму.

### 🛠 1. Первоначальная настройка Git (Выполняется один раз)

Для начала необходимо представиться системе и настроить безопасный доступ, чтобы GitHub понимал, кто отправляет код.

**Шаг 1: Представьтесь Git'у**
Эти данные будут отображаться в истории ваших коммитов.

```bash
git config --global user.name "Ваше Имя"
git config --global user.email "ваша.почта@example.com"

```

**Шаг 2: Настройка безопасного доступа (SSH)**
Поскольку GitHub больше не поддерживает доступ по паролям, создадим SSH-ключ:

```bash
# Генерируем новый ключ (нажимайте Enter на все вопросы, чтобы оставить пути по умолчанию)
ssh-keygen -t ed25519 -C "ваша.почта@example.com"

# Запускаем ssh-agent в фоне
eval "$(ssh-agent -s)"

# Добавляем ключ в агент
ssh-add ~/.ssh/id_ed25519

# Выводим публичный ключ в терминал для копирования:
cat ~/.ssh/id_ed25519.pub

```

> **Внимание:** Скопируйте полученный текст, зайдите на GitHub -> **Settings** -> **SSH and GPG keys** -> **New SSH key**, и вставьте его туда.

**Шаг 3: Проверка связи**

```bash
ssh -T git@github.com
# Успешный ответ выглядит так: "Hi <username>! You've successfully authenticated..."

```

### 🧬 2. Как использовать этот код (Fork или Свой проект)

Вы можете использовать этот репозиторий двумя способами: помочь в развитии оригинальной **Psych Ward OS** или взять её за основу для создания собственной, независимой микроядерной системы.

#### Вариант А: Стать контрибьютором (Fork & Pull Request)

Используйте этот метод, если хотите предложить свои улучшения и драйверы в этот репозиторий.

1. Нажмите кнопку **Fork** в правом верхнем углу страницы репозитория на GitHub.
2. Склонируйте *свой* форк на локальный компьютер:
```bash
git clone https://github.com/<ВАШ-NICKNAME>/psych-ward-os.git
cd psych-ward-os

```


3. Вносите изменения, отправляйте их в свой форк (командой `git push`) и нажимайте **New Pull Request** на GitHub.

#### Вариант Б: Создать свою ОС на этой базе (Template)

Если вы хотите взять этот код как стартовый шаблон и развивать его как независимый проект:

1. Склонируйте оригинальный репозиторий:
```bash
git clone https://github.com/dzen25/psych-ward-os.git
cd psych-ward-os

```


2. Создайте новый **пустой** репозиторий (без README и `.gitignore`) в своем аккаунте GitHub.
3. Отвяжите локальный код от оригинала и привяжите к своему новому репозиторию:
```bash
# Меняем адрес удаленного репозитория на ваш новый (рекомендуется SSH)
git remote set-url origin git@github.com:<ВАШ-NICKNAME>/<НАЗВАНИЕ-ВАШЕГО-РЕПОЗИТОРИЯ>.git

```


4. Отправьте весь код в свой репозиторий:
```bash
git push -u origin main

```



> 🎉 **Готово!** Теперь это полностью ваш независимый проект. Все последующие вызовы `git push` будут отправлять код только к вам.

### 🔄 3. Базовый рабочий процесс (Сохранение изменений)

Когда вы внесли правки в код (например, обновили драйвер VFS), используйте этот стандартный цикл для фиксации и публикации:

```bash
# 1. Посмотреть статус (покажет измененные и новые файлы)
git status

# 2. Добавить все изменения в индекс (подготовка к сохранению)
git add .

# 3. Создать коммит — зафиксировать состояние с понятным описанием
git commit -m "Added FAT32 write support via DMA"

# 4. Отправить зафиксированные изменения на GitHub в ветку main
git push origin main

```

### 🛡 4. Безопасная разработка и полезные команды

При разработке операционной системы (например, при написании нового сетевого стека) лучше изолировать свои эксперименты, чтобы случайно не сломать стабильную сборку.

**Безопасные эксперименты (Ветвления):**

```bash
# Создать новую ветку для экспериментов и сразу переключиться на неё
git checkout -b feature/virtio-net

# ... пишем код, делаем git add и git commit ...

# Вернуться обратно на стабильную основную ветку
git checkout main

# Слить экспериментальную ветку в основную (когда драйвер протестирован)
git merge feature/virtio-net

```

**Шпаргалка полезных команд:**

```bash
# Стянуть последние изменения из облака (полезно, если работаете с разных ПК)
git pull origin main

# Посмотреть красивую историю коммитов (кто, когда и что менял)
git log --oneline --graph --decorate

# ОТКАТ: Отменить изменения в конкретном файле (вернуть к последнему коммиту)
git checkout -- <путь_к_файлу>

```
